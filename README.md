# RunGap（ラン・ギャップ）

**理想と現実の"差"を数値で見る、ランニングフォーム比較 Web アプリ**

版：v0.16（企画段階）／最終更新日：2026-07-28
対象：愛知工業大学 陸上競技部 長距離ブロック（競技者・指導者）／利用は無料

---

## 一言でいうと

使用者の体型を反映した 3D モデルに、本人が選んだ「理想の走り」をさせ、実際の走行動画と比較して、**体の各部位が理想からどれだけ数値的に離れているか**を提示する Web アプリです。

「正しいフォーム」を教えたり採点したりはしません。提示するのは、あなた自身が選んだ理想との**差分の数値だけ**です。

---

## 設計思想（このプロジェクトの中核）

> **「正解を押し付けない計測器」であること。**

- アプリの役割は、理想の走りと現実の走りの**差分を数値で提示するところまで**。
- その数値をフォーム改善に取り入れるか、どの指標を優先するかは、**選手・指導者本人の判断に完全に委ねる**。
- 評価・採点・ランク付け機能は意図的に搭載しない。差が大きいことは「悪い」ことを意味しない。
- UI 文言でも「診断」「判定」「スコア」「改善点」という語は使用禁止とし、「比較」「差分」「数値」「記録」に統一する。

この思想を、UI 文言・画面設計・通知設計のすべてに一貫して反映させることを、開発全体の第一原則とします。

## コア機能（F1〜F7：Phase 1）

- **F1 体型入力・3D モデル生成** … 身体数値からボディラインを反映した 3D アバターを生成
- **F2 理想モーション登録** … お手本動画からモーションを抽出し、自分のアバターへ角度ベースでリターゲット
- **F3 環境条件入力** … 風速・風向・気温・傾斜・路面・ペースを設定（トラック周回モデルに基づく風の扱い）
- **F4 走行動画アップロード・解析** … 撮影ガイド付きでアップロード、サーバーで姿勢推定
- **F5 差分比較・数値提示**（核心機能）… 6 指標を「理想値／あなたの走り／差」で提示、評価語なし・信頼度併記
- **F6 3D 並走ビューア** … 理想アバターと実走アバターを重ね／並べて再生
- **F7 履歴管理** … 差分の推移を折れ線グラフで閲覧、自由記述メモ付き

Phase 2 で指導者共有（F8）、Phase 3 で写真自動採寸・リアルタイム型・ネイティブ対応（F9〜F11）を予定。

## 設計上、特に注意している点

- **中立性の徹底**：数値の独り歩き（差分＝悪という誤解）を防ぐため、差の大きさは数値のみで示し、バーや色の濃淡・警告色（赤）は用いない。各指標に解説（「？」）を付す。
- **側方単眼カメラの制約の明示**：真横 1 台では手前脚が奥脚を遮蔽（オクルージョン）するため、接地時間の左右値は複数歩から統計推定し、値ごとに信頼度（高・中・低）を併記する。左右差重視の計測は将来の後方・前方カメラ追加がより適することを明記。
- **絶対長（cm）の較正**：単眼映像には絶対的な長さ情報がないため、F1 で入力した身体寸法（身長・股下長）を 3D 骨格に当てて画素↔実長のスケールを求め、ストライド長などを cm 換算する。cm 精度は体型入力値と骨格スケール推定の精度に依存する。
- **精度の限界を隠さない**：単眼推定には誤差がある。誤った数値を断定的に見せないことも「計測器」としての誠実さの一部とする。

## 開発フェーズ

- **Phase 0（2〜3 ヶ月）** … 単眼姿勢推定の精度検証（最大のリスクを最初に潰す）。基準（参照値）は Sony mocopi（関節角度）＋ Garmin/Coros のランニングダイナミクス（接地時間・ピッチ・ストライド長・接地時間の左右バランス）を同時計測して用いる。両者とも推定値のため、真値との誤差ではなく複数推定の一致度として検証する。判断基準例：膝関節角度差 ±5°以内、接地時間差 ±20ms 以内。具体的な実施手順は別紙 `Phase0_精度検証手順書.md` にまとめている
- **Phase 1（4〜6 ヶ月）** … Web アプリ初版（F1〜F7、事後解析・手動体型入力）
- **Phase 2（2〜3 ヶ月）** … 指導者共有・履歴グラフ拡充
- **Phase 3（時期未定）** … 写真自動採寸／リアルタイム型／iOS・Android ネイティブ対応

## 技術構成（概要）

- 3D 表示：Unity（WebGL ビルド）
- 姿勢推定：サーバー側 GPU の機械学習モデル。Phase 0 で次の 4 系統を比較選定 —— ①RTMPose／MMPose 系（軽量 2D 検出）、②ViTPose 系（高精度 2D）〔①②は 2D→3D 積み上げ型〕、③人体メッシュ復元型（SMPL 系・CameraHMR 等）、④拡散・フローマッチング系（FMPose3D 等）
- サーバー：大学研究室の GPU サーバー（オンプレミス）を採用。開発初期はローカルサーバーで構築・検証し、運用開始時は初期利用者を 2〜3 名に限定して段階的に拡大
- バックエンド：Python（FastAPI 等）＋ ジョブキュー
- データベース：PostgreSQL 等
- プライバシー：動画原本は解析後 30 日で自動削除。体組成データは本人と許可した指導者のみ閲覧可。研究室サーバー運用のためデータは学外に出ない
