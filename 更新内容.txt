■ 更新内容
  姿勢推定パイプライン設計の Step 1（動く土台）を実装した。共通スケルトン
  ＋ PoseEstimator インターフェース ＋ ダミーアダプタで、パイプラインを
  端から端まで通し、1本の入力から結果が出る状態を確認した。

  1. パッケージ rungap_pipeline を新規作成した。
     - skeleton（共通スケルトン）／estimators（抽象・レジストリ・ダミー
       アダプタ）／calibration（cm較正）／gait（接地検出・局面）／
       metrics（6指標の簡易算出）／confidence（信頼度の一次付与）／
       schema（出力＝score/rank/grade を持たない中立スキーマ）／
       evaluation（評価モード＝Phase 0 の一致度）／pipeline（統括）／
       run（端から端までの実演）で構成。
     - 実行すると metric_comparisons（理想／実測／差／信頼度／局面別）の
       JSON と、評価モードの一致度テーブル（採用見込み／要注意）が出る。
       数値はダミー（合成モーション）で、配線の実証が目的。
     - 下流（正規化・検出・較正・指標・3D）はモデル非依存のため、最終
       選定モデルに依らず再利用でき無駄にならない。

  2. README のドキュメント一覧に実装コードを追加し、全ドキュメントの版を
     v0.11 に更新した（開発案・取扱説明書・Scrapboxは内容変更なく版のみ）。
     最終更新日は 2026-07-28 のまま。

■ 理由
  「精度確認を先送りして4系統で開発を進めたい」という方針を、共通パイプ
  ライン＋差し替え式アダプタ＋評価モードとして具体化する第一歩を、動く
  コードとして確定するため。

  「精度確認を先にせず、4系統でアプリを開発できないか」という発案者の
  問いを受け、精度検証を工程として切り離すのではなく、姿勢推定を差し替え
  可能にした共通パイプラインへ畳み込む方針を採り、その設計書を新規作成した。
  最初に載せるモデルは2本（軽量2D＋メッシュ復元）から始める。

  1. 姿勢推定パイプライン・モデルアダプタ設計を新規作成した。
     - モデル非依存の共通パイプライン（前処理→姿勢推定アダプタ→共通
       スケルトンへ正規化→cm較正→歩行周期検出→6指標算出→信頼度付与→
       出力）を定義。
     - 共通インターフェース PoseEstimator（擬似コード）、共通スケルトン、
       初期2モデルのアダプタ（A:軽量2D＝スケール不定・要cm較正、
       B:メッシュ復元＝メートルスケールでcm較正と相性良）を記載。
     - 評価モード：参照（mocopi・ウォッチ）との一致度検証をコードの一部
       として取り込み、Phase 0 を使い捨てにしない設計とした。
     - 信頼度は評価モードの結果で指標×条件ごとに較正する方針を明記
       （精度の把握が製品機能＝信頼度表示の材料になる点を反映）。
     - 中立性：パイプラインは評価・採点を出力せず、差・信頼度・局面別の
       みを算出する方針を再確認。

  2. 判断の記録：4系統を「アプリ内で並べても、どれが正しいかは参照が
     なければ判断できない」ため、精度確認は省略ではなく評価モードとして
     アプリ開発に内包する方針とした。共通の後段（正規化・検出・較正・
     指標・3D）は最終選定モデルに依らず再利用でき無駄にならないため、
     ここから着手する。

  3. README のドキュメント一覧に設計書を追加し、全ドキュメントの版を
     v0.10 に更新した（開発案・取扱説明書・Scrapboxは内容変更なく版のみ）。
     最終更新日は同日中のため 2026-07-28 のまま。

■ 理由
  発案者の「開発を前に進めたい」という意向を、精度の判断材料を捨てずに
  満たすため、姿勢推定を差し替え式にした共通パイプラインの設計を確定し、
  文書間で参照関係を保つため。

■ 更新内容
  未確定事項の一つ「Phase 0の評価環境（精度の基準）」を確定し、関連
  ドキュメントへ同期反映した。残る未確定は「利用規約・同意文面の最終
  確定」の1件のみとなった。

  1. Phase 0の精度検証で用いる「基準（参照値）」を確定した。
     - 関節角度系（膝関節角度・体幹前傾角・腕振り角度）：Sony mocopi
       （6点IMUによるモバイルモーションキャプチャ）を参照値とする。
     - 時間・距離系（接地時間・ピッチ・ストライド長）および左右差：
       Garmin/Coros のランニングダイナミクス（接地時間・ピッチ・
       ストライド長・接地時間の左右バランス）を参照値とする。
       ※接地時間・左右バランスの取得には胸ストラップ（HRM-Pro等）
         またはランニングダイナミクスポッドが必要（手首のみでは不可）。
         Corosは対応機種・POD等により出力項目が異なるため要確認。
     - この2機種で比較指標6項目を分担してカバーできる。特に、側方単眼
       の弱点であった「接地時間の左右差」を、Garmin/Corosの左右バランス
       で外部から補える点が大きい。
     - 光学式（マーカー式）モーションキャプチャは不要とした。

  2. Phase 0の位置づけを「一致度検証」として明確化した。
     - mocopi・Garmin/Corosはいずれも推定値であり、厳密な真値
       （ゴールドスタンダード）ではない（mocopiは研究上、相対的に
       低精度なモーションデータとして扱われる場合がある）。
     - よってPhase 0は「真値との誤差測定」ではなく「動画推定・mocopi・
       ウォッチという複数の独立した推定の一致度検証」と位置づける。
       動画推定が両参照値から大きく外れる指標を要注意として抽出する。
       これはアプリの「精度の限界を隠さない」思想とも整合する。
     - 実務上の留意点：3系統（動画・mocopi・ウォッチ）を同時計測し
       時刻同期する必要がある。動画とmocopiは開始時の同期マーカー
       （手拍子等）で合わせる。Garmin/Corosの接地時間は秒単位・平均
       寄りの粒度のため、1歩ごとでなく一定区間の平均で比較する。
     - 判断基準（例）は従来どおり：膝関節角度差±5°以内、接地時間差
       ±20ms以内。参考として、接地検出が20msずれると低速でも膝角度が
       最大約7°変わるという報告があり、両基準は独立でなく連動する。

  3. 各ドキュメントへ反映した。
     - 開発案：7.3（3D姿勢推定の選定基準）、9章Phase 0（基準の記述を
       差し替え・一致度検証として明記）、12章（未確定→確定へ移動）。
     - README：未確定事項・確定済注記、開発フェーズPhase 0の記述。
     - Scrapbox：未確定事項・確定済、開発フェーズPhase 0の記述。

  4. 全ドキュメントの版を v0.5 に更新した（README／開発案／取扱説明書／
     Scrapbox）。取扱説明書はPhase 0が利用者向けでないため内容変更は
     なく版番号のみ更新。最終更新日は同日中の更新のため 2026-07-27 の
     まま据え置いた。

■ 理由
  Phase 0（単眼姿勢推定の精度検証）という最大リスク検証の前提を確定し、
  開発着手の判断ができる状態にするため。あわせて基準が推定値である事実を
  明示して、Phase 0の解釈が過信に傾かないようにするため。
